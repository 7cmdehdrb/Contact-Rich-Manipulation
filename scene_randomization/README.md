# 시뮬레이터 없는 밀기 Scene 랜덤화 검증

작업판 위 실린더의 초기 배치를 NumPy로 생성하고, 전체 Scene의 기하 조건과 밀기 방향·거리 분포를 검사한다. **Tool/Wrist가 항상 월드 좌표의 -y 공간을 점유하므로, RED와 넓은 GRAY 캡슐을 전면까지 확장한다.** 그림 생성은 Matplotlib로 분리했다. Isaac Sim, Isaac Lab, 로봇 모델을 불러오지 않는다. 모든 길이 단위는 **cm**다. 최종 수식과 전체 생성 순서는 [최종 로직](LOGIC.md)을 참고한다.

## 실행

저장소 루트에서:

```bash
python -m pip install -r scene_randomization/requirements.txt
python -m scene_randomization --count 10000 --seed 20261013
```

이 작업 환경의 기본 `python`에는 Matplotlib이 없고, 기존 `env_isaaclab` 환경에는 NumPy와 Matplotlib이 모두 설치되어 있다. 이 환경으로 실행하려면:

```bash
MPLCONFIGDIR=/tmp/scene_randomization_mpl /home/min/miniconda3/envs/env_isaaclab/bin/python \
  -m scene_randomization --count 10000 --output outputs/scene_randomization
```

`outputs/scene_randomization/`에 생성되는 파일:

| 파일 | 내용 |
|---|---|
| `gallery.png` | 전체 각도 범위를 골고루 보여주는 12개 Scene |
| `scene_0000.png` | 첫 번째 Scene 확대 그림 |
| `distribution.png` | 방향·거리 히스토그램과 결합분포 |
| `zone_logic.png` | 기존 캡슐과 Tool/Wrist를 고려한 확장 Zone 비교 |
| `report.json` | 생성 속도, 재시도 수, 전체 기하 검사, 분포 통계, 사용 설정 |
| `scenes.npz` | 전체 Scene의 좌표·명령·접근 경로·설정 |

기본 그림 저장은 화면 없이도 동작하는 `Agg` 백엔드를 사용한다. 저장된 Scene을 데스크톱 창에서 넘겨 보려면 GUI 백엔드가 있는 환경에서 다음 명령을 실행한다. 슬라이더, Prev/Next/Random, 좌우 방향키, `r` 키를 지원한다.

```bash
python -m scene_randomization.viewer outputs/scene_randomization/scenes.npz
```

병렬 생성이나 다른 난도 설정:

```bash
python -m scene_randomization --count 10000 --workers 2 --no-plots
python -m scene_randomization --count 10000 --config scene_randomization/example_config.json
python -m unittest scene_randomization.test_generator -v
```

`--no-save-scenes`로 NPZ 저장도 생략할 수 있다. **생성 시간은 검증·시각화·파일 저장을 제외한다.** 검증 시간은 별도 기록한다. Scene당 시간은 배치 생성 총시간을 Scene 수로 나눈 값이며, 개별 API 호출의 지연시간과는 다르다.

## 원안에서 변경한 생성 순서

원안의 `D ~ Uniform(D_min, D_available)`은 타겟 위치와 각도마다 상한이 달라져, 짧은 거리를 더 자주 생성할 수 있다. 각도도 배치 실패 후 함께 재생성하면 쉬운 방향에 몰릴 수 있다.

이 구현은 **방향·거리 → 가능한 타겟 위치 → 접근 경로 → 장애물** 순서를 사용한다.

1. 방향 `[0, 2π)`과 거리 `[5, 20]`의 결합 공간을 기본 **24 × 8** 구간으로 나눈다. 매 주기마다 192개 구간을 무작위 순서로 한 번씩 방문하고, 각 구간 안에서는 연속 균일분포로 샘플링한다. 배치를 여러 번 생성해도 같은 `SceneGenerator`의 스케줄이 이어진다. 새 생성기를 만들 때는 별도 seed를 사용한다.
2. 변위 `Δ = D(cosθ, sinθ)`를 먼저 고정한다. 가능한 타겟 직사각형은 `T_safe ∩ (W_obj − Δ)`다. 이 교집합에서 타겟 위치를 균일하게 샘플링한다. 타겟의 **무조건부 위치 분포는 원안의 직사각형 균일분포와 달라진다.** 방향·거리 분포를 우선한 의도적인 선택이다.
3. 배치 재시도 시 타겟 위치·접근 경로·장애물만 다시 만든다. **방향·거리 명령은 유지한다.** 시도 상한에 도달하면 해당 인덱스와 명령을 포함한 `GenerationError`를 반환한다. 실패한 Scene을 버리고 성공한 것만 모으는 방식으로 처리하면 다시 분포 편향이 생길 수 있으므로, 오류를 명시적으로 처리해야 한다.
4. 모든 방향과 최대 거리에서 유효한 위치가 존재하지 않는 설정은 생성 전에 거절한다. 길이 범위가 기하적으로 불가능할 때 특정 각도를 숨겨서 제외하지 않는다. 장애물까지 배치할 수 있는지는 유한한 재시도로 확인한다.

생성기를 처음 만든 시점부터 누적한 `n`개에서 각 결합 구간의 개수 차이는 최대 1개다. 모든 표본이 독립인 IID 샘플링은 아니며, 구간 내 연속값을 무작위화한 층화 샘플링이다. 중간 주기에서 잘라낸 배치에서는 두 주기의 일부가 겹쳐 구간 개수 차이가 2개까지 날 수 있다. 각도·거리 구간 수는 설정으로 바꿀 수 있다.

병렬 생성에서도 명령 스케줄을 부모 프로세스에서 만들고, 각 작업 프로세스에 서로 다른 난수 스트림과 명령을 전달한다. 프로세스 수를 바꿔도 명령은 같다. 장애물 좌표는 프로세스 수에 따라 달라질 수 있으며, 같은 seed·설정·호출 방식에서는 재현된다.

## 기하 조건

기본 작업판은 `[-50, 50] × [0, 40]`, 실린더 반지름은 4, 높이는 10이다. 기본 벽/상판 경계 여유 0.5를 적용하면 물체 중심 영역은 `[-45.5, 45.5] × [4.5, 35.5]`이다. 타겟 시작 영역은 `[-30, 30] × [12, 28]`이다.

| 규칙 | 구현 |
|---|---|
| RED | 반경 8.3의 타겟 경로 캡슐을 **월드 -y 방향으로 전면까지 확장**. 장애물 중심 배치 금지 |
| GRAY | 반경 14의 경로 캡슐도 -y로 확장하고, 뒤쪽 `16 × 22` 직사각형을 더한 뒤 새 RED를 제외 |
| WHITE | 중심 배치 가능 영역에서 RED·GRAY를 제외 |
| 장애물 수 | 총 6개: GRAY 3개, 그중 뒤쪽 최소 1개를 먼저 배치; WHITE 3개 |
| 초기 표면 간격 | 타겟 포함 모든 초기 물체 쌍에 `≥ 0.8 × 2 = 1.6`; 중심 거리 `≥ 9.6` |
| 격자 제한 | 실제 작업판을 5열 × 2행으로 분할, 셀당 물체 최대 3개, 타겟 포함 |
| 국소 밀도 | 각 물체 중심 반경 18 안의 다른 물체 최대 3개. 새 후보뿐 아니라 기존 물체의 이웃 수도 검사 |
| 전역 분산 | 유효 후보 중 현재 물체 수가 적은 셀에 더 높은 선택 확률 부여 |
| 상판/벽 | 초기 물체와 최종 목표가 물체 중심 안전 영역 안에 존재 |

기본 최소 표면 간격은 초기 배치에 적용된다. 이동 중 타겟과 -y로 이어지는 점유 영역의 장애물 여유는 RED 여유 0.3으로 검사한다. 뒤쪽 장애물은 새 RED 밖에 남은 원래 뒤쪽 영역에서 배치한다. 일반 GRAY 후보는 전면부터 확장 Zone 전체를 포함하는 직사각형에서 뽑고 실제 Zone에 속하는지 검사한다. 높이는 저장 정보이며 2D 충돌 계산에 사용하지 않는다. 그림의 Zone 색은 **장애물 중심의 허용 영역**을 뜻하므로, 장애물 원의 외곽이 Zone 경계에 걸치는 것 자체는 위반이 아니다.

## 접근 가능성을 빠르게 보장하는 방법

Scene마다 격자 탐색을 실행하는 대신, **연속 접근 경로 하나를 먼저 확보**한다.

- 손가락을 유효 두께 2의 원, 즉 반지름 1로 근사한다.
- 전면 밖 `y = -2`에서 타겟 아래쪽으로 수직 진입한다.
- 타겟 주변의 반지름 5.25인 16각형에서 짧은 방향으로 돌아 목표 방향 반대편에 도달한다. 선분 전체가 타겟과 손가락의 확장 반지름을 피하도록 설정을 검사한다.
- 마지막 0.25를 진행해 `p_contact = p_target − (4 + 1)d`의 접촉점에 도달한다.
- 장애물 후보는 이 경로의 모든 선분에서 중심 거리가 `4 + 1 + 0.1 = 5.1` 이상이어야 한다. 경로를 먼저 확보하므로 사후 접근 실패로 Scene을 버릴 필요가 없다.
- 각 경로 꼭짓점이 측면·후면 벽 안에 있고, 선분 전체의 확장 장애물 충돌을 분석적으로 검사한다. 전면에는 벽을 두지 않는다.

이 방법은 장애물이 없는 **손가락 접근 경로의 존재**를 보장한다. 하나의 경로만 확보하므로 주변 GRAY 물체는 계속 배치된다. 확보한 경로 때문에 장애물 위치 분포는 전체 유효 배치 공간의 균일분포가 아니며, 방향·거리의 균등성을 보장하는 목적에 맞춘 구성이다.

검사 범위는 **타겟의 직선 이동, 밀기 구간의 Tool/Wrist -y 점유 규칙, 작은 원으로 근사한 손가락의 접근**이다. GRAY는 Tool/Wrist 주변의 여유 영역이며, GRAY 장애물이 작은 원 모델과 실제로 충돌해야 한다는 조건은 없다. `scenes_with_hand_push_interference`는 이 원 모델의 밀기 구간 간섭 수를 별도 표시한다. Tool/Wrist 규칙은 기존 RED 캡슐을 -y로 확장한 기하 모델이며, 실제 손바닥·손목·팔 형상과 운동학을 사용하지 않는다. 접근 중 Wrist 전체의 점유, 로봇 도달 가능성, 전도·마찰·물체 이동도 포함하지 않는다. 접촉으로 다른 장애물을 이동시켜 접근하는 확장 모드도 구현하지 않았다. 현재 모드는 첨부한 기본 모드다.

## 속도 구조와 실패 처리

Scene 축을 NumPy로 벡터화한다. 최대 장애물 수만큼 순서대로 배치하되 각 단계의 후보 32개 × Scene 수를 한 번에 검사한다. 기본 chunk는 512개로, 수만 Scene에서도 후보×경로 선분 배열이 지나치게 커지지 않게 한다. 난도와 메모리에 따라 `candidates`, `chunk_size`를 조정할 수 있다.

`workers=1`도 수천 Scene을 배치로 처리한다. `workers>1`은 CPU 프로세스 병렬 처리이며 프로세스 시작/데이터 전달 비용이 있으므로 적은 Scene 수에서는 오히려 느릴 수 있다. 그래프 그리기와 파일 저장은 생성 경로 밖에서 수행한다.

현재 모델의 속도와 전체 기하 검증 결과는 [최종 로직](LOGIC.md)의 검증 결과와 저장된 `report.json`에서 확인할 수 있다. 병렬 실행 시간에는 프로세스 시작과 결과 수집도 포함된다. 하드웨어·부하·난도에 따라 시간은 달라진다.

배치 실패 시 간격·밀도·Zone·방향 조건을 자동 완화하지 않는다. CLI는 `failure.json`에 실패 명령과 설정을 기록하고 종료 코드 2를 반환한다. 기하 검증 실패는 종료 코드 1, 정상 완료는 0이다.

## Python API

```python
from scene_randomization import Config, SceneBatch, SceneGenerator, validate_scenes

generator = SceneGenerator(Config(), seed=123)
batch = generator.generate(4096)
next_batch = generator.generate(4096)  # 누적 방향×거리 균형 유지
assert validate_scenes(batch)["valid"]

target_xy = batch.target                 # (4096, 2)
goal_xy = batch.goal                     # (4096, 2)
obstacle_xy = batch.obstacles            # (4096, 6, 2)
angle_radians = batch.angle              # (4096,)
push_distance = batch.distance           # (4096,)
approach_xy = batch.approach             # (4096, 11, 2), 끝점 반복 패딩 가능

batch.save("scenes.npz")
loaded = SceneBatch.load("scenes.npz")
```

장애물 배열 순서는 뒤쪽 GRAY → 나머지 GRAY → WHITE다. 기본 인덱스 0은 뒤쪽, 0~2는 GRAY, 3~5는 WHITE다. 뒤쪽 개수는 먼저 지정한 수를 반드시 배치하며, 나머지 GRAY도 뒤쪽에 들어갈 수 있다. NPZ에는 seed 대신 사용 설정과 최종 좌표가 저장된다. 재생성용 seed와 프로세스 수는 `report.json`에 저장된다. 사용 모델은 `zone_model="wrist_downward_v2"`로 기록한다. 모델 정보가 없는 이전 NPZ는 기존 캡슐 규칙으로 생성되었으므로, 로더가 재생성을 안내하며 거절한다.

검증 코드는 후보 수용 결과를 그대로 신뢰하지 않고 반환된 좌표에서 선분 거리, -y 확장 영역 거리, 물체 간 거리, 모든 물체의 밀도, Zone, 벽, 접촉 자세를 다시 계산한다. 자동 테스트는 4,096개 Scene의 전체 조건에 더해 수평·수직·대각선 확장, 상단 경계 보존, 독립적인 기하 계산과의 일치, 확장 GRAY 전면 샘플링, 분포 균형, 재현과 실패 처리 등을 확인한다.
