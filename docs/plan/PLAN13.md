Refactor-v3_1 환경을 기준 삼아서, 이를 계승하는 새로운 환경을 만들어라. 이름은 Refactor-Relative-v0 으로 삼는다.
상속을 해도 좋고, 안해도 좋다. 여러 변경점이 있을 예정이기 때문이다.

0. 중요 고정 사항
    1. 현재 EEF 좌표축 기준으로 OSC를 사용한다. 
    2. Contact 함수는 3개 중 2개 접촉 시 인정 구조이며, Distance 보상에는 코사인 유사도를 사용한다.
    3. Action Rate는 _1 환경을 기준으로 삼아 사용한다.
    4. 대부분의 관측의 기준점을 EEF Frame 기준으로 변경한다. 
        - 단, EEF POSE는 base 기준 유지한다. 안그러면 항상 0.0.0.0.0.0.1이니까.

1. Actor와 Critic이 지금은 서로 다른 관측을 사용하는데, 이를 통일한다.
    - 기존의 주요 차이점은, Target의 State가 Initial/Current인지, 장애물 관측이 G.T. 인지 관측 가능한 것 & 확률 변조인지 이다.
    - 이를 Actor 기준으로 맞춘다. Critic Network도 Actor와 동일한 관측을 가져가게 만든다. Rollout Stoarge도 동일한 것을 사용한다.
    - Reward Function 쪽에서는 G.T 값을 가지고 계산하나, 이는 어디까지나 리워드 계산 시에만 사용하는 것이며, 관측에 포함되지 않는다.

2. Hand 설정을 필요시 변경한다.
    - Actuator 설정 중, URDF에 정의된 사항이 있으면 이를 반영한다. Max Vel, Max Effort 등이 주요 대상이다.

3. 장애물 인코더를 변경한다.
    - 기존에는 Base Frame 기준으로 장애물 위치를 받아서 학습 시켰는데, 이를 변경한다.
    - EEF Frame 기준으로 장애물 위치를 받아서, 같은 방식으로 벡터를 구성, MLP를 학습한다.
    - 단, "관측 가능한 장애물" 의 선정 조건은 변경하지 않는다. 단순히 지금 관측의 좌표계만 변경한다고 생각해라.

4. 타겟 위치 관측을 변경한다.
    - 타겟 위치의 생성 규칙 등은 동일하나, 이를 관측하는 것을 변경한다.
    - XYZ 3차원으로 표현하며, 현재 EEF에 대한 상대 좌표로서 표현한다.

5. Tactile 관측을 변경한다. 
    - 센서 구성은 손바닥-손등 센서가 1:1로 매핑되는 구성으로 잡아놨다.
    - 기존에는 이걸 펴서 17+17 차원으로 표현하나, 이를 압축하고자 한다.
        Palm	Dorsal	의미	인코딩
        0	0	접촉 없음	0
        1	0	손바닥 접촉	+1
        0	1	손등 접촉	-1
        1	1	양쪽 접촉	+2
    - 위와 같은 상태 표현 방식으로 사용해라.

6. target_goal_first_entry_bonus 계수 변경
    - 25 -> 10으로 대폭 하향한다.

이 과정에서 내가 원하는 수정 외의 다른 수정 사항은 없으며, 저번처럼 환경 바꿨더니 물체 스폰이 이상해져서 물체가 허공에서 떨어지거나 이상한 타이밍에 스폰된다거나, 리워드나 관측을 내가 원하지 않은 방향으로 수정하는 현상은 절대 있어서는 안된다.
내가 의도한 수정만 가해졌는지 코드리뷰를 통해 검토하고, 최종 종료하라.
