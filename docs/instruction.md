리워드 함수를 설계할 때 수행할 작업은 **평가 목적 정의 → 항 구성 검토 → 함수 특성 확인 → 실제 동작 분석 → 가중치 조정 → 성능 검증**으로 정리할 수 있습니다.

**1. 보상으로 유도하려는 행동을 먼저 정의한다**

수식을 만들기 전에, 무엇을 잘했다고 평가할지 정리합니다.

| 목적 | 유도하려는 행동 | 점검할 문제 |
|---|---|---|
| 접근 | 손이 대상 물체에 가까워짐 | 가까이 머무르기만 해도 보상을 계속 얻는가? |
| 접촉 유지 | 물체와 접촉을 지속함 | 밀지 않고 접촉만 유지하는 행동을 선호하는가? |
| 목표 방향 이동 | 물체를 목표 위치에 가깝게 이동시킴 | 잘못된 방향의 이동이나 접촉 해제로 페널티를 회피할 수 있는가? |
| 주변 물체 보호 | 주변 물체에 가하는 힘과 변위를 줄임 | 필요한 가벼운 접촉까지 과도하게 억제하는가? |
| 동작 안정화 | 충격과 급격한 동작을 줄임 | 필요한 움직임까지 억제하여 정지하게 만드는가? |

각 항에 대해 **“보상하려는 행동”과 “의도하지 않았지만 보상을 얻을 수 있는 행동”**을 함께 적는 것이 첫 작업입니다.

**2. 항 사이의 중복과 상충을 검토한다**

각 보상 항의 입력 변수, 활성화 조건, 평가 목적을 표로 정리하고 다음을 확인합니다.

- 같은 행동을 여러 항에서 중복 보상하거나 중복 처벌하는가?
- 한 항이 장려하는 행동을 다른 항이 억제하는가?
- 여러 항으로 나눌 필요가 있는가, 하나의 식에서 표현할 수 있는가?
- 항을 분리했다면 각각의 역할과 분리 이유가 명확한가?

여기서 독립성은 **모든 항을 수학적으로 완전히 독립시키라는 의미보다, 중복과 의존 관계를 파악하고 의도적으로 구성하라는 의미**로 해석하는 것이 적절합니다. 거리 감소·증가 항이 동시에 활성화되지 않는다는 사실만으로 다른 보상 항과의 관계까지 검토된 것은 아닙니다.

**3. 함수의 크기와 민감도를 사전에 확인한다**

예상되는 입력 범위에 대해 보상 함수를 그려 다음을 점검합니다.

| 확인 항목 | 수행할 작업 |
|---|---|
| 출력 범위 | 원래 함수값과 가중치 적용 후 값의 범위를 계산 |
| 무반응 구간 | 행동이 달라져도 보상이 변하지 않는 구간 확인 |
| 포화 구간 | 상한·하한에 걸려 행동 차이가 반영되지 않는 구간 확인 |
| 문턱·불연속 | 조건을 조금 넘었을 때 보상이 급격히 바뀌는지 확인 |
| 민감도 | 같은 크기의 입력 변화가 구간별로 보상을 얼마나 바꾸는지 확인 |
| 계수 간 결합 | 접촉 여부·방향 계수 등을 곱했을 때 전체 항이 지나치게 자주 0이 되는지 확인 |

목표는 모든 함수를 선형으로 만드는 것이 아니라, **실제 평가하려는 행동 범위에서 필요한 차이를 구분하도록 만드는 것**입니다.

**4. 실제 동작과 각 보상 항을 스텝별로 기록한다**

전체 환경 평균에 더해, 개별 에피소드의 변화를 확인할 로그를 확보합니다.

- **행동·상태:** 손의 변위 또는 속도, 타겟과의 거리, 목표 거리, 접촉 여부, 접촉력, 주변 물체 변위 등.
- **보상:** 각 항의 원값, 가중치 적용값, 전체 보상.
- **조건:** 각 항의 활성화 여부와 문턱·클리핑 적용 여부.

이후 동일한 시간축으로 그려 **“어떤 행동 때문에 어떤 항이 변했는가”**를 확인합니다. 성공 사례뿐 아니라 접촉 실패, 정지, 충격, 목표 이탈 등 실패 사례도 포함합니다.

**5. 실제 기여도를 확인하고 함수·가중치를 조정한다**

각 항에 대해 다음을 비교합니다.

| 분석 대상 | 확인할 내용 |
|---|---|
| 활성화 빈도 | 대부분 0인지, 거의 항상 발생하는지 |
| 값의 분포 | 평소 크기와 드물게 발생하는 큰 값의 차이 |
| 시간적 변화 | 지속적으로 반응하는지, 특정 순간에만 급변하는지 |
| 누적 기여 | 에피소드 전체에서 어느 항의 기여가 큰지 |
| 상황별 상대 크기 | 접근·접촉·밀기·정지 구간에서 어느 항이 우세한지 |

**가중치 0.3과 0.7이 실제 영향력 30%와 70%를 의미하지는 않습니다.** 또한 누적 보상 비율만으로 학습 영향력을 단정하지 않고, 발생 시점과 실제 행동 변화를 함께 봐야 합니다.

함수가 대부분 포화되거나 활성화되지 않는다면 **입력 범위·문턱·함수 형태를 먼저 검토**하고, 정상적으로 반응하지만 상대적인 크기가 부적절할 때 가중치를 조정합니다.

**6. 수정 근거를 남기고 성능으로 검증한다**

수정할 때마다 다음 네 가지를 기록합니다.

1. **관측한 문제:** 예를 들어 접촉 보상은 계속 발생하지만 이동 보상은 거의 발생하지 않음.
2. **원인 가설:** 접촉 유지의 이득이 이동의 추가 이득보다 커서 정지하는 것으로 추정.
3. **변경 사항:** 어떤 함수·조건·가중치를 왜 바꾸었는지.
4. **검증 결과:** 보상 발생 양상과 실제 행동이 예상대로 바뀌었는지, 성공률·정확도·안정성이 개선되었는지.

교수님과 논의할 자료는 **① 보상 항 정의표, ② 함수 그래프, ③ 실제 동작과 보상의 시간 그래프, ④ 수정 전후 비교표**로 준비하면 됩니다.
